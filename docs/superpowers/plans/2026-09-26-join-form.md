# Join Form Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a real, accessible, on-brand player-application form on `/join/` that never claims delivery it cannot perform, and is ready to wire to our own Worker endpoint later without UI changes.

**Architecture:** A mandated `submitForm()` interface with swappable adapters (mock now, own Worker endpoint later), a single `JoinForm.astro` UI that never imports a provider, and an honesty rule that forbids a success state while no endpoint exists.

**Tech Stack:** Astro 7 static output + Cloudflare adapter, TypeScript strict, Biome, Vitest, Playwright + axe, pure-Node gates. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-26-join-form-design.md` — binding. Executors read it; conflicts resolve against it.

## Global Constraints

- `contracts/FORM-CONTRACT.md` is FROZEN: no form logic in an Astro page; the UI depends only on `submitForm(payload): Promise<FormResult>`; no provider payload shapes in UI.
- **Honesty rule (binding):** v1 must never render a success state. `unavailable` → notice + real channels. A pre-submit notice warns the form is not yet live so no typed data is lost unknowingly.
- Zero new dependencies. `packages/truth` stays `zod`-only; gate scripts stay pure Node.
- Tokens-only CSS values; never hand-edit `apps/web/src/styles/generated/`.
- Native browser validation *rules* (`required`, `type=email|tel|url|date`) are the source of truth; presentation is ours (see Task 2).
- Accessibility contract-bound: real labels, `aria-describedby` hints, focus-managed error summary, one `h1` + sequential `h2`s, no colour-only required indication.
- `/join/` keeps `noindex={true}` in v1 (Phase 2 content/SEO decision, not a silent flip).
- Biome: single quotes, semicolons, 2-space.
- No new routes. `ROUTE-CONTRACT.md` untouched.

**Interfaces:**
- Consumes: FORM-CONTRACT `submitForm(payload): Promise<Result>`
- Produces:
  ```ts
  export type JoinApplication = {
    fullName: string; dateOfBirth: string; nationality: string;
    countryOfResidency: string; phone: string; email: string;
    statisticsUrl?: string; videoUrls?: string[];
  };
  export type FormResult =
    | { status: 'ok' }
    | { status: 'unavailable' }
    | { status: 'error'; message: string };
  export type FormAdapter = (payload: JoinApplication) => Promise<FormResult>;
  export function submitForm(payload: JoinApplication): Promise<FormResult>;
  export function setFormAdapter(next: FormAdapter): void;
  export function resetFormAdapterForTests(): void;
  ```
  `FormResult` is a discriminated union; consumers narrow on `status`. `setFormAdapter`
  is the swap seam (the module-level `let adapter` binding) and is paired with
  `resetFormAdapterForTests` — without the setter the reset is inert and any
  adapter-swap test would pass vacuously. UI code calls `submitForm` only.

### Task 2: `JoinForm.astro` — fields, validation presentation, honesty UI

**Files:**
- Create: `apps/web/src/components/JoinForm.astro`
- Read: `apps/web/src/components/Button.astro`, `apps/web/src/components/PageBanner.astro`, `packages/truth/src/contracts/*.contract.md` (component-contract shape), `apps/web/src/styles/base.css` (form-control precedent + focus-ring pattern)
- Test: `pnpm --filter @ukbt/web exec vitest run` (regression), plus targeted Playwright in Task 4

**Interfaces:**
- Consumes: `submitForm`, `JoinApplication`, `FormResult` from Task 1
- Produces: `<JoinForm />` with no required props; renders the 8 live fields, the disabled upload field, the pre-submit notice, and the result region.

- [ ] **Step 1: Markup for all fields**

One `<form novalidate>` (we present errors ourselves) with a `<label for>` per control, `autocomplete` on name/tel/email, `aria-describedby` for the phone country-code hint and the one-URL-per-line hint. Required state appears in the label text, not colour alone. Upload field: `disabled` + `aria-describedby` pointing at a visible "photo uploads open with online applications" explanation. Result region: `<div role="status" aria-live="polite">` rendered empty initially.

- [ ] **Step 2: Validation presentation using the browser's own rules**

Small inline module script: on submit, prevent default, read `input.validity.valid` / `validationMessage` for each control, build an error summary `<ul>` of failing fields, render it into a focusable container (`tabindex="-1"`) and focus it; set `aria-invalid="true"` on failing controls. No hand-written validation rules and no regexes — `type=`/`required` remain the rule source. Guard re-init with a `window.__ukbtJoinFormWired` once-guard, matching the existing ClientRouter pattern in `apps/web`.

- [ ] **Step 3: Honesty UI**

Above the submit button, a visible notice that online applications are not open yet and that the club's current channels are the working route. On submit, `submitForm` returns `unavailable` → render into the live region: "Online applications are not open yet" + the real contact channels. **No success state exists in this component** — do not add one.

- [ ] **Step 4: Visual treatment**

Design-system reuse only: `Button` for submit, existing tokens for spacing/colour/type, focus rings from the established pattern, reduced-motion-safe (no new motion). No new tokens unless provably required.

- [ ] **Step 5: Verify**

Run: `pnpm lint && pnpm typecheck && pnpm --filter @ukbt/web exec vitest run`
Expected: clean; existing tests unaffected.

- [ ] **Step 6: Commit**

```bash

git commit -m "feat(join): application form component (a11y errors, honesty notice)"
```
